# THE UNMADE — Main Quest, Returning People, and Unreal Scene Factory
**2026-10-10 | Full source-authoring handoff; Unreal Editor compilation still pending**

## Three connected production systems

### Main story (authoritative mechanics vs authored presentation)
The **entire nine-realm main campaign** now has a structured interaction contract in `Authoring/main_quest_interaction_contracts.json`, including the two frontier first quests, three middle alternatives, Eillun/Tharniv, Auvren, and the Reach opening. For **each of the nine realms**, six explicit steps are defined: arrival, investigation, physical mechanism, mutually exclusive care choice, mutually exclusive truth choice and a return encounter. That's **54 fully written quest beats**, each with actual dialogue text, exact trigger, physical action, failure state, recovery and saved outcome. Nhal-Vey's mask, unveiled core, future choice and epilogue are a separate four-beat ending contract. Seven canonical progression gates tie those paths to the existing `UnansweredRoad` state rules.

**No new mandatory completion-counter has been added.** Reach visits, existing `FrontierJourney`, `LaterRealmJourney` and `FinalJourney` remain authoritative. The six later-realm quests reference the existing actual C++ evidence/mechanism tags and the validator rejects fabricated later-realm tags. The opening/first two frontier scene tags are **honestly marked as visual authoring placeholders** until their exact runtime actor counterparts are bound inside UE. Do not use these placeholders to force progress in gameplay. Quest text/choices in this JSON are production specifications; existing live source still handles the actual quest stage, bridge collision, witness, save and reward. The authored dialogues have not all been converted to game UMG dialogue-tree nodes.

**Editor data:** `Authoring/generated/main_quest_steps_unreal.csv` (54 rows), using `FUnmadeQuestStepAuthoringRow`. Row identity is `QUEST_MAIN_<Realm>_<step>`. Never rename it after Blueprint references exist. DataTable rows are *read-only content references*, not an authority for bypassing save guards. The `physical_tag` field identifies live later-realm tags or pending early-realm staging hints; check `contract_status` in JSON before assigning Blueprint triggers.

### Returning people and relationships
All **82 existing residents** retain their original stable ids: **48 Threefold**, **16 Frontier** and **18 later-realm** inhabitants. The portable C++ `ResidentContinuity` holds personally visited game-day counts, last conversation day and a single personally aided bit per resident. Repeat Talk on the same game day does not farm familiarity, day reversals are rejected and return familiarity saturates at five levels. The optional schema-1 `ResidentEncounterVisits`, `ResidentEncounterLastDays` and `ResidentEncounterAidFlags` fields are saved through the same existing slot. Malformed arrays block writes rather than overwriting unrelated quest state; a failed write restores the prior relationship snapshot.

The native source now records conversations from the **actual E-to-NPC** interaction and personalized aid from the **actual OfferAid event**; the existing independent observer/rumor system still owns witnessed versus secondhand information. Returning `AUnmadeNpcCharacter::GetReactionText` consults the saved relationship and only shows individual authored return lines when a resident has met the player **on at least two distinct game days**. The individual lines are keyed by the same 82 ids in `Authoring/resident_return_encounters.json`, compiled into `Source/TheUnmadeGame/Public/Authoring/UnmadeResidentReturnData.h` and exposed through `Authoring/generated/resident_returns_unreal.csv` + `FUnmadeResidentReturnAuthoringRow`. A citizen's public-quest observation is restricted to the citizen's own region; they don't gain remote personal memories magically. Returning into Held or Many Mornings produces a distinct, locally framed line, but never changes who helped them or invalidates past testimony.

**What is not complete:** full multi-turn branching conversation interfaces, every character's individualized animation/voice, deep personal relationship quests, localization and actual NPC motion/navmesh parity across nine authored maps. The authoring pack defines each person's concern and next-visit hook but those optional quests must be physically staged before being called implemented.

### Repeatable, guarded Unreal scene factory
A standalone Python3.11 offline generator `Scripts/build_story_scene_handoff.py` consumes the canonical main-quest, resident, nine-realm production and cinematic JSON masters. Run:
```bash
python Scripts/build_story_scene_handoff.py --check
python Scripts/unreal_editor/stage_world_manifest.py
```
Both work without Unreal: the second prints a **dry-run inventory**. It describes 52 non-colliding, stable-name authoring references: four modular prop/quest/camera references for each of nine realms (36) and 16 cinematic reference points. Staging locations derive from existing source-defined world origins plus safe offsets; their labels are `UM_STG_<Realm>_<Index>` and `UM_STG_SHOT_S01` through `S16`. The JSON manifest is `Authoring/generated/scene_build_manifest.json`, produced deterministically from the two world/cinematic masters.

**First Windows Unreal PC (explicit apply only):**
1. Run `Scripts/check_unreal_host.ps1` and `Scripts/first_pc_build_and_test.ps1`. It checks `build_world_content.py --check`, `build_cinematic_handoff.py --check` and **the new** `build_story_scene_handoff.py --check` before Editor compilation. Resolve any native/UHT errors before continuing.
2. Enable the Unreal Editor's **Python Editor Script Plugin** and Editor Scripting Utilities if required by your installation. Create a **new empty staging level**, save/open it under a package whose active world name contains `Unmade_AuthoringStaging`. This safety requirement prevents accidental changes to a real game level.
3. Execute `Scripts/unreal_editor/stage_world_manifest.py --apply` using the UE Python execution interface (e.g. the Editor Python command tool, passing argv as supported by your UE installation). The importer loads the explicit 52-source manifest, checks its dedicated level, and **creates only non-colliding placeholder cube actors** with stable labels. Existing labeled stage actors are skipped. Gameplay tags/state, source-spawned `UnmadePrototypeHub` mechanisms, and SaveGame are not modified.
4. Run it again to verify **idempotency**: it should create 0 and skip 52 actors. It saves the new staging level if and only if it added actors. If you manually renamed references, it may add missing labels—restore original names before rerunning.
5. Import the CSVs as real DataTables via Content Browser. Use `FUnmadeQuestStepAuthoringRow` for `DT_UnmadeMainQuestSteps`, `FUnmadeResidentReturnAuthoringRow` for `DT_UnmadeResidentReturns`. Also import the earlier 9-realm and 16-shot cinematic source and the 9/18/10 world authoring tables. Verify 54+82+9+16+9+18+10 rows.
6. Reimport generated tables when source JSON changes; do not hand-edit generated data or manually recopy hundreds of lines.
7. Replace one staging block at a time with a real high-quality modular prop and hook its Blueprint behavior **to the already working native source tags and quest rules**, never to cosmetic shot-completion flags. Preserve all original collision, encounter, narration and SaveGame guards.
8. Create a true Level Sequence for each cinematic shot ID using the prior timed cinematic CSV, add cameras, voice/subtitle tracks, and use the staging shot guide to keep the first edit coherent. The 16 actors are *camera position references*, not an automatically rendered UE Sequencer timeline.
9. Test gamepad, sightline, accessible text, cross-realm travel, physical branching, corruption/failed saves, direct memory versus rumors, both main-path choices, final boss, post-victory realms and optional rematch before treating any stage as shippable.

## Always-on acceptance
Run `python -m unittest discover -s Scripts/tests -v` and the native `Tests/npc/resident_continuity_test.cpp` in GitHub CI. The generator refuses to shift the order of all 82 resident IDs, because that would silently assign saved relationship data to the wrong person. The realm quest generator refuses mismatched atlas IDs, fabricated six-later-realm mechanism tags and missing failure/recovery branches. The Editor importer refuses a non-staging world, duplicate IDs, invalid coordinates and any actor configured as colliding.
