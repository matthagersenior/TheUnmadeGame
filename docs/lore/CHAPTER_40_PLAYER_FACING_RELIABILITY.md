## Chapter 40 Player Facing Reliability

A remembered world needs decisions the traveler can read and controls that say what they actually do. This chapter records the six follow-up audit fixes to recovery, prompts, physical trade, character choice, combat presentation and behavioral verification. All nine realm adventures retain their existing actors, rewards and consequences. The changes do not select a protagonist, settle wages, override consent or resolve an OPEN mystery.

### 40.1 Recovery that can be understood

Recover Backup now previews the loss of unsaved session changes and requires the same recovery action again for the same selected profile. It never saves the current session before loading, because that could replace the backup the traveler is trying to recover. A confirmation for recovery cannot authorize a normal load or a new game. Changing the profile, changing pages, closing the menu or explicitly saving clears the pending request.

Normal loading and creating an unused profile still try to save first. When that fails, their repeated confirmation belongs to the selected profile and intended operation. Existing files remain intact. The Session page displays these warnings and save results inside the open menu. A warning sent only to a hidden HUD notice would not be a reviewable choice.

The portable confirmation rules exercise different profiles, different operations, canceled requests and failed writes. Actual storage interruption and engine travel remain acceptance work. Compatible backups retain their earlier policy; an incompatible future schema is not silently normalized into the current version.

### 40.2 Controls without a second interpretation

Prompt formatting now reads each original input token once. It chooses the longest matching label at that position and appends its mapped display name without interpreting that display name again. If attack is rebound to Left Shift and dodge is rebound to Z, the attack instruction stays Left Shift. The word Shift inside its generated label cannot become Z.

Ordinary words, adjacent Unicode text and identifiers remain untouched. The first-person pronoun remains a pronoun unless the existing inventory or equipment instruction supplies its context. The same tested formatter feeds physical signs, objectives and menu guidance. The menu compares already formatted text before updating its body, avoiding repeated updates caused only by a label substitution.

Actions now includes Toggle Sneak. It uses the actual existing crouch movement and detection checks, and can be reached through controller menu navigation. Sneaking grants no invisibility. The original keyboard hold controls remain available. Twenty-eight action buttons and eight menu pages include the new Character page.

### 40.3 Trading with a person in the room

Buying and selling require a living traveler, the real registered local merchant, their existing consent, range and an unobstructed visibility trace. The same portable policy handles both transaction directions. A merchant on the other side of a wall is not a usable shop merely because their position is nearby.

Existing money, prices, reputation, stock rules and atomic inventory transactions remain authoritative. This pass does not invent a remote merchant, a new currency or a permission to trade after refusal. Generated collision and merchant routines still need a real engine walkthrough to establish that the intended counter and approach are usable.

### 40.4 Choosing the person who returns

The Character page exposes the existing chosen-name setter and all eight registered identity aspects: body frame, face, hair, voice, skin palette, reality mark, gait and calling. Next Feature selects an aspect. Previous Option and Next Option cycle only its registered choices. The name field and Save Chosen Name button submit the existing validated name path. Each successful edit is saved; a rejected name or failed save retains the earlier identity.

The origin remains The Impossible. These controls do not overwrite the protagonist with one canonical literary name. The existing prototype silhouette applies its implemented frame, gait and palette choices. Face, hair, voice and mark values remain saved selections pending their final presentation assets. The menu states that limit directly. It does not claim a completed wardrobe, face sculptor or newly recorded voice library.

The Character page displays edit success and failure while it is open. Keyboard focus, controller navigation, platform virtual keyboard behavior and the rendered identity must be checked in Unreal. This is native source access to persistent choices, not proof that every final art variant has imported.

### 40.5 Injury before another performance

The enemy motion priority rule now protects the full held stagger from lower priority cues, including Guard, Attack and Seal. Another injury can retain stagger; Death can interrupt it. Once defeated, an actor cannot switch away from death presentation. A held ordinary attack still blocks immediate replacement by idle or walk.

The rule operates on the existing animations and presentation durations. It does not change damage, recovery windows, stamina costs or the authored boss mechanics. The sound library and fifty-seven prototype clips remain retained. Contact synchronization, clip replay, blending, body transforms and the audio mix remain engine acceptance requirements.

### 40.6 Audit behavior and then check again

The repeatable dependency audit now executes production-rule cases for scoped confirmation, replacement labels, obstructed trading and motion priority, alongside the previous progression, save and recipe tests. Identity tests exercise every registered option and valid round trips, and refuse invalid changes without mutation. Source checks confirm that the native adapters use these tested rules and that all twenty-eight action callbacks have actual definitions.

The follow-up inspection found and fixed invisible menu feedback as well. This is the reason for checking again after a repair: a working policy can still be connected to an interface that hides its explanation. The complete source suite and repeatable audit remain the gate for the next pass. Their success does not certify an Unreal executable; collision, focus, imports, performance and complete nine-realm playthroughs remain explicitly deferred.
